# Streak rules

The normative description of how Duongöndro counts streaks. `internal/streak` is the reference implementation, and `testdata/streak-cases.json` holds conformance cases that the Go, iOS and Android implementations must all pass unchanged. Background and reasoning: [design: Social](https://github.com/Duongondro/duongondro-design/blob/main/docs/06-social.md#streaks).

## Inputs

For one practice (or, for the headline streak on Today, all practices merged):

- **Events**, each with a `kind`:
  - `session`: a logged practice, with `start` (an instant), `tz` (the IANA time zone the phone was in at the start) and optionally `day` (`YYYY-MM-DD`), the user's explicit choice in the after-midnight sheet.
  - `bardo`: a freeze covering one missed day, with `day` and `tz`; it has no start.
- **Seed** (optional): an imported streak `{days, lastDay, tz}`.
- **Now** and **nowTz**: the moment of evaluation and the phone's current time zone.

## Definitions

- **Civil date** of an instant in a zone: its Gregorian year, month and day in that zone. Never a week-based year, never the device's calendar.
- **startOfDay(d, z)**: the first instant of civil date `d` in zone `z` (local midnight; if midnight does not exist there because of a DST jump, the first instant that does).
- **Day of an event**: `day` if given, else the civil date of `start` in `tz`.
- **Effective instant**:
  - `session`: `min(start, startOfDay(day + 1, tz) − 1 s)`. Without an override this is `start`; with the override to an earlier day it is the last second of that day, so a session counted for Sunday is treated as done by Sunday's end.
  - `bardo`: `startOfDay(day, tz)`.
- **Deadline** after a practice day `d` whose events used zones `Z`, seen from zone `n`:
  `max over z ∈ Z ∪ {n} of startOfDay(d + 2, z)` — midnight at the end of the next day, in whichever zone gives the most time.

## Algorithm

Sort events by effective instant (ties: sessions before bardo days, then input order). State: `count` (including the seed), `tracked` (excluding it), `lastDay`, the zone set `Z`, and whether a streak has started.

1. With a seed: `count = days`, `tracked = 0`, `lastDay = seed.lastDay`, `Z = {seed.tz}`, started.
2. For each event with day `d`, zone `z` and effective instant `t`:
   - **Nothing started**: a session starts a streak (`count = tracked = 1`, `lastDay = d`, `Z = {z}`); a bardo day is ignored.
   - **`d ≤ lastDay`** (same date, or an earlier date after flying west over the date line): add `z` to `Z`; counts do not change.
   - **`t <` deadline after `lastDay` with `Z`, seen from `z`**: the streak continues. A session adds one to `count` and `tracked`; a bardo day adds nothing. Then `lastDay = d`, `Z = {z}`.
   - **Otherwise** the streak broke. A session starts a new one (`count = tracked = 1`, `lastDay = d`, `Z = {z}`); a bardo day leaves nothing started.
   - After each event, `longest = max(longest, count)` and `longestTracked = max(longestTracked, tracked)`.
3. At `now`: if a streak has started, `deadline` = deadline after `lastDay` with `Z`, seen from `nowTz`. The streak is alive if `now < deadline`; then `current = count` and `currentTracked = tracked`, otherwise both are 0.

## Outputs

`current`, `currentTracked`, `longest`, `longestTracked`, `lastDay` (or null), `deadline` (an instant, or null).

**Public streaks and the leaderboard use `currentTracked` and `longestTracked` only**; the seed counts on the user's own screen. Streak numbers count practice days, not calendar days: a date skipped by crossing the date line eastwards does not add a day, and a date repeated by flying west adds nothing the second time.

## Conformance cases

Each entry in `testdata/streak-cases.json` has `name`, optional `seed`, `events`, `now`, `nowTz` and `expect` with all six outputs (`deadline` in UTC). The expected values were worked out by hand from this document, not generated by the reference implementation.
